# SecretProvider

`Bxx\Settings\SecretProvider` загружает все INI-файлы из `local/secrets`. Файлы нужны только для удобной группировки, а секреты адресуются по имени секции и ключа. Это отдельное хранилище: секреты не входят в публичную конфигурацию `Bxx\Settings`.

## Формат файлов

Например, `local/secrets/integrations.ini`:

```ini
[telegram]
orders = "BOT_TOKEN"

[webhooks]
webhook = "WEBHOOK_SECRET"
```

Можно создавать несколько файлов и распределять секции между ними. Разные ключи одной секции объединяются. Пара секция-ключ должна быть уникальной среди всех файлов; дубликат приводит к `RuntimeException`.

## Чтение секретов

```php
use Bxx\Settings\SecretProvider;

$token = SecretProvider::get('telegram', 'orders');
$webhookSecret = SecretProvider::get('webhooks', 'webhook');
```

Третий аргумент задаёт значение по умолчанию, если секция или ключ отсутствует:

```php
$token = SecretProvider::get('telegram', 'orders', '');
```

`getAll()` возвращает все секции, а `getAll('telegram')` — ключи только выбранной секции:

```php
$allSecrets = SecretProvider::getAll();
$telegramSecrets = SecretProvider::getAll('telegram');
```

## Поведение и безопасность

- Обрабатываются файлы `*.ini` непосредственно в `local/secrets`, относительно корня сайта. Вложенные каталоги не сканируются.
- В каждом файле используйте INI-секции; ключи верхнего уровня вне секций не поддерживаются.
- Все файлы загружаются и кэшируются при первом обращении в статическом свойстве. После изменения секрета долгоживущему процессу может потребоваться перезапуск.
- Если секции или ключа нет, `get()` возвращает default (`null`, если он не задан); `getAll()` для отсутствующей секции возвращает пустой массив.
- Ошибка разбора INI, отсутствие секций или дубликат ключа приводит к `RuntimeException`.
- Не добавляйте файлы секретов в Git и ограничьте права на чтение на уровне файловой системы.
- `.htaccess` закрывает каталог для Apache. Для Nginx необходимо отдельно запретить HTTP-доступ к `/local/secrets/` в конфигурации веб-сервера.
