# Защита служебных каталогов

**Важно:** каталоги `local/options`, `local/secrets`, `local/.logs`, а также скрытые файлы и каталоги не должны быть доступны по HTTP. Правила `.htaccess` не защищают их на Nginx: запрет нужно настроить в конфигурации виртуального хоста.

Добавьте правила внутрь соответствующего блока `server {}`:

```nginx
location ~* ^/local/(options|secrets)(/|$) {
    deny all;
}

location ~ (^|/)\.(?!well-known(?:/|$)) {
    deny all;
}
```

Первое правило закрывает `/local/options` и `/local/secrets` целиком. Второе блокирует URL с компонентами пути, начинающимися с точки, в том числе `/local/.logs/`, `/.git`, `/.github`, `/.dev` и `.env` в любом каталоге. Оно оставляет доступным `/.well-known` для ACME challenge. Если исключение не нужно, замените второе правило на `location ~ (^|/)\.`.

Проверьте, что в конфигурации нет более приоритетного `location ^~`, обходящего эти regex-location. После изменения выполните `nginx -t` и перезагрузите конфигурацию Nginx. `deny all` должен возвращать запрет доступа (обычно HTTP 403).
